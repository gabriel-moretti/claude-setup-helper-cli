# Template — Spike

```
Spike — <o que precisa ser investigado>

Como usar: spike é investigação com prazo, não desenvolvimento. Produz uma DECISÃO ou
ENTREGÁVEL, não código de produção. Se virou "vou codando pra ver", não é mais spike.

1. Pergunta a responder
Uma pergunta específica. Se forem várias, provavelmente são vários spikes.
<ex: "NestJS ou FastAPI pro backend do CRM?">

2. Por que agora / o que destrava
<O trabalho ou decisão que está travado esperando essa resposta.>

3. Opções / hipóteses a avaliar
* <opção A>
* <opção B>
* <...>

4. Critérios de decisão
Os eixos que realmente importam. Definir ANTES de investigar evita viés.
* <ex: curva de aprendizado do time>
* <ex: fit com a stack atual / esforço de manutenção>
* <ex: custo / prazo / performance>

5. Entregável
<recomendação escrita / ADR / POC descartável / doc comparativo>

6. Quando parar
<data/hora limite — quando o tempo acabar, decide com o que tem. Não estende sozinho.>

7. Resultado / decisão (preencher no fim)
* O que foi descoberto: <...>
* Decisão: <a escolha + o porquê>
* Próximo passo: <qual story/feature isso libera agora>
```
